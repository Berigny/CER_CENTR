What it checks


Everything spec/store-0.md lists for an export. The manifest must be exactly the canonical one for its size, and each segment file must hash to its manifest entry. Every line is checked in seq order: its form, the hash chain, the received times and epochs, each object and attestation under evidence/0, and each checkpoint against the lines before it and its witness by the store key. The report lists every finding up to the maximum. It has no free text, so the same files give the same bytes in every implementation.


The page orders the segment files as the manifest lists them. A listed file that was not chosen is passed as empty bytes and gets S_SEGMENT_HASH. If the manifest itself is invalid, the files named with six digits and .jsonl are used in name order. Other files are ignored.







Serving this page


Browsers load neither ES modules nor WebAssembly from a file:// URL, so the page must be served over HTTP. From the repository root:


sh tools/build-wasm.sh
python3 -m http.server 8000 --bind 127.0.0.1


Then open http://127.0.0.1:8000/tools/verify-page/. To host it elsewhere, copy tools/verify-page/ and crates/evidence-wasm/pkg/ keeping their relative layout. The page requests only its own files and the module from its own origin.
